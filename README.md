# 知材 · 新工作流建立

这是一个帮助你和 AI 智能体一起管理长期项目的 Skill。它会引导智能体把项目目标、任务、进度、工作规则和交接信息整理成文件，保存在你选择的项目文件夹里。

## 它解决什么问题？

- **新对话接不上之前的工作**：把做到哪里、还有什么问题、下一步做什么写进项目文件。开启新对话时，让智能体读取这些文件，再继续推进。
- **任务和完成标准说不清楚**：建立任务清单，写明每项任务要交出什么、怎么检查、哪些内容不碰。
- **智能体做完就说完成，但没有检查**：为项目建立检查和验收规则，记录实际检查结果；需要你审核的任务，等你确认后再标记完成。
- **换一个智能体后需要重新交代项目**：把项目说明、进度和交接信息放在项目文件夹里。另一个有权限读取这些文件的智能体可以先了解项目，再接着做。
- **已有项目文件散乱，不知道还缺什么**：先盘点现有文件，列出可以沿用和需要补充的内容。涉及修改已有文件时，先征求你的同意。

## 它怎么帮你建立工作流程？

1. 先了解你想做什么、项目放在哪里、怎样才算完成。
2. 列出准备建立的文件和第一批任务，等你同意后再创建。
3. 建立项目说明、任务清单、进度记录、交接文件和检查规则。
4. 检查已创建的文件，并告诉你检查结果和下一步。

你也可以让它检查已有项目。智能体会先盘点已有文件，再给出建议；如果只想先建一个简单的项目占位，也可以选择轻启动，以后再补全。

文章、学习、研究、运营、产品等需要持续推进的项目都可以用这套方式。实际效果取决于智能体能否读取、创建文件或运行命令，以及使用环境的权限。项目文件可以帮助新对话接续，但仍需实际检查智能体是否读到了文件。安装 Skill 本身不会自动修改已有项目。

## 一个具体例子：和 AI 一起做公众号文章

下面是一个示例，用来说明对话和项目文件如何配合。实际提问和输出会因你的项目、智能体和环境而有所不同。

### 第一步：建立项目

安装 Skill 后，你对智能体说：

> 请用「新工作流建立」Skill，帮我建立一个公众号文章项目。文章根据我提供的读书笔记来写。先了解我的需求，列出准备建立的文件，等我同意后再创建。

智能体会询问项目放在哪里、要交出什么、怎样才算完成等信息。例如，你告诉它：项目放在桌面的「公众号写作」文件夹；第一项任务是根据你的读书笔记写一篇公众号文章。完成标准是：字数 1200～1800 字、有标题和分节、引用能对应到你提供的资料。写好后先给你审核，不自动发布。

智能体根据这些信息列出计划。你确认后，它会建立项目文件，例如：

```text
公众号写作/
├── AGENTS.md              项目做什么、有哪些工作规则
├── feature_list.json      任务、验收步骤和状态
├── progress.md            当前进度和下一步
├── session-handoff.md     已完成的事、未完成的事和交接信息
├── docs/harness/          检查和收尾规则
└── deliverables/          任务产出
```

它还会说明启动检查的结果。项目建立完成后，智能体先停下，不会自行开始写文章。

### 第二步：让智能体开始做任务

你把读书笔记交给智能体，然后说：

> 开始第一项任务，根据我提供的笔记写文章。写完先自查，把草稿给我审核，不要发布。

智能体按项目中的要求完成任务、检查草稿，并记录结果。假设草稿已经写好、检查通过，但你还没看，交接信息可以是这样：

```text
当前任务：根据读书笔记写第一篇公众号文章
目前进度：草稿已完成，等待用户审核
草稿位置：deliverables/F-01-writing/draft.md
已经检查：字数、标题和分节、引用与提供的资料是否对应
下一步：请用户阅读草稿，按反馈修改
```

这些内容会根据实际完成情况写入进度、任务清单和交接文件。没有做过的检查应标明未完成。

### 第三步：换一个新对话，接着做

下次打开新的智能体对话，把工作位置设为「公众号写作」项目文件夹，然后说：

> 请先读取这个项目的说明、进度、任务清单和交接记录，告诉我现在做到哪里、哪些内容等我审核。先不要修改或发布。

如果智能体能够读取这些文件，就可以根据记录告诉你：第一篇草稿已完成、放在哪里、还在等你审核。你看过后可以继续说：

> 我看过草稿了，请把第二节的例子写得更清楚。改完后再给我审核。

智能体就可以按你的反馈继续修改，并更新任务状态和进度。你可以对照项目文件检查它是否读对了；是否能自动读取、是否能操作文件，取决于智能体的能力和权限。

## 安装

在电脑终端运行：

```bash
npx skills add hanzcbk-droid/zhicai-new-workflow-starter -g
```

跟随提示选择 `zhicai-new-workflow-starter` 和你使用的智能体。`-g` 表示安装到个人环境，供多个项目使用；去掉 `-g` 则默认安装到当前项目。

运行命令需要 Node.js 22.20 或更高版本，以及可以访问安装器和 GitHub 的网络。

如果你不熟悉终端，也可以把下面这段话发给**能够操作你电脑文件和运行命令的智能体**：

> 请帮我安装知材的 `zhicai-new-workflow-starter` Skill。先检查我的环境是否能安装，运行 `npx skills add hanzcbk-droid/zhicai-new-workflow-starter -g`，让我选择需要安装的智能体；安装后检查 `SKILL.md`、`references/` 和 `templates/` 是否完整，告诉我结果。

安装完成后，开启新对话，或者按所用智能体的方式刷新 Skill 列表。不同智能体的安装和加载方式可能不同；如果没有自动发现，可以手动指定 `SKILL.md` 文件的位置，请智能体读取。安装器不支持的平台，请按该平台的说明安装整个 `zhicai-new-workflow-starter` 文件夹，保留其中的 `references/` 和 `templates/`。

## 怎么使用

在已经安装 Skill 的智能体中说：

> 请用「新工作流建立」Skill，帮我建立一个长期写文章的项目。先问我需要的信息，给我看计划创建的文件，等我同意后再创建。

或者处理已有项目：

> 请用「新工作流建立」Skill 检查这个项目已有的文件，告诉我哪些已经满足需要、哪些缺失。先列出建议，不要覆盖现有文件。

完整项目通常会有 `AGENTS.md`（项目说明）、`feature_list.json`（任务清单）、`progress.md`（进度）、`session-handoff.md`（接续交接）和验证、收尾等文件。Skill 自身包含的模板是工具资料，**不需要全部复制进每个项目**；实际创建哪些文件，按你的选择和所用智能体的能力确定。

建好以后，建议打开一个新对话，问智能体：“这个项目是做什么的，现在做到哪里，下一步是什么？”对照项目文件检查回答，确认接续是否有效。

## 环境与验证情况

- 能读写文件并运行命令的智能体可以执行完整建档和脚本检查；不能运行命令时可按人工检查清单执行。不能写文件时会提供完整内容和路径供你保存；没有实际读回或检查的部分会标明未验证。
- macOS / Linux / WSL 的启动检查使用 Bash；其中任务清单的自动检查需要 Python 3。Windows 启动检查使用 PowerShell。
- 当前本地版本已做结构检查、macOS Bash 检查和 macOS PowerShell 7 脚本测试；Windows 系统上的运行和不同智能体的新对话接续尚未完成实测。平台行为会随版本变化，请以实际验证为准。
- 启动脚本检查任务编号、状态、验收步骤和证据格式；它不能判断证据是否真实充分，仍需对照实际结果核实。
- 脚本只自动检查原模板中的已知占位项，自己新增的占位内容需要人工检查；代码、JSON 和公式中的正常大括号不按占位符处理。
- `references/agent-compat.md` 保留原有平台说明，其中记录的时间为 2026-10-23；使用前请结合当前平台版本验证。

## 更新

发布后可参考安装器的 `npx skills check` 和 `npx skills update` 命令检查及更新支持的安装。更新 Skill 不会自动升级已经建立的项目；如需调整已有项目，请先让智能体盘点并征得你的同意。
