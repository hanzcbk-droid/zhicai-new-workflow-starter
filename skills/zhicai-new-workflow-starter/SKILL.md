# 知材 · 新工作流建立 v2.0

目标：建好之后，任何智能体开一个全新对话，只读项目文件夹里的文件，就能答出五件事：这是什么项目、文件怎么组织、怎么开工、怎么验收、现在做到哪了。

## 铁律
- 跟用户说话一律用大白话。不甩术语，非用不可时先用一句话解释、再举个例子。每个问题都给推荐选项，并告诉用户"拿不准就选推荐"。
- 可选的东西不替用户做主：用户没明确说"要"，就不加。
- 用户没明确说"行"，不往磁盘写任何文件。要覆盖或修改已有文件，再单独问一次。
- 没有"多久不回复就当同意"这回事。等不到回复就停着。
- 项目信息只写进项目文件夹，不写回本 Skill。
- 模板从 templates/ 复制后填写，不凭记忆重写。

## 第 0 步：先判断自己能干什么（自己判断，不问用户）
- 能不能写文件？能不能运行命令？是什么操作系统？
- A 档，能写也能跑：生成 init.sh（Windows 生成 init.ps1），建完马上运行一次。
- B 档，能写不能跑：不生成脚本，改用 docs/harness/startup-check.md 逐条人工检查。
- C 档，不能写：确认用户同意方案后，逐个给出完整文件内容和存放路径，请用户自行保存。不能代写项目文件或项目总表；用户保存后，只有确实有权限读回和运行检查时才能执行相应操作，否则给出人工检查清单，明确说明未写入、未读回或未检查，不能声称通过。

## 第 1 步：看目标位置已经有什么
- 是空的或还不存在：新建模式。
- 有东西但没有 AGENTS.md：接管模式。先列出已有文件，按 references/audit.md 的「旧项目接入」对照，只补缺的，不动用户原有的文件。
- 已经有 AGENTS.md：体检模式。按 references/audit.md 打分并给建议，用户逐条同意后再改。
- 新建模式下，用户只给了个名字、说"先建着""先占个位"：先问一句"要先简单占个位（只建文件夹和一份说明书草稿），还是现在就把整套建好？"。选占位的，只建文件夹 + AGENTS.md（标题后注明"草稿 v0.1，待补全"），明确说明尚未建立完整工作流及交接机制，汇报后停下。以后用户说"补全"，先按体检和旧项目接入流程盘点，再按确认后的方案补全完整架构。

## 第 2 步：问用户（话术见 references/interview.md）
- 不知道项目总表放在哪时，先问问题 0。知道了就不再问；平台有记忆功能的，把总表位置记进去。
- 第一轮问基本情况（问题 1～5），第二轮问可选模块（问题 6～8）。每轮最多 5 个问题。
- 问题 3（怎么算做好）不能跳过，至少要拿到 3 条能逐条检查的标准。
- 用户回答"随便""你定"时：基本信息用推荐值，在清单里标【默认】；可选模块一律先不加，并告诉用户以后随时可以补。

## 第 3 步：列清单，等用户说"行"
用大白话列出：建在哪个路径；哪些是项目必备、哪些因能力或平台而选、哪些是用户选择的可选模块；每个文件附一句中文说明；第一批 1～3 个任务写清交付、检查和范围。Skill 包文件是工具和模板，不需全复制进项目。用户说"行"再动手。

## 第 4 步：建文件
- 完整项目必建：AGENTS.md、feature_list.json、progress.md、session-handoff.md、DECISIONS.md、docs/harness/verification.md、docs/harness/closing.md、docs/harness/lessons.md、deliverables/。A 档加对应系统的 init 脚本，B 档加 docs/harness/startup-check.md。
- 用户会用 Claude Code：建 CLAUDE.md。已经有 CLAUDE.md 的，不覆盖，先问用户能不能在第一行加上 @AGENTS.md。
- 用户选了才建：changelog.md、docs/harness/workflow.md、docs/harness/loop.md。
- 建完整项目时初始化 session-handoff.md：写明当前状态、实际已验证与尚未验证的内容、未解决事项及下一步；没有开展的如实写“尚未开始”。检查完成后同步记录检查结果。
- 工作流文件名使用英文、数字、连字符、下划线和点；中文名写在文件里的标题上。用户指定的项目文件夹名称照用户的选择。
- 所有 {占位符} 都要换成真实内容。问题 3 的标准写进 verification.md。
- 新项目中新建且尚未开始的任务标 not_started；接管旧项目时，按 references/audit.md 保留真实状态并处理证据待核的历史任务，不把旧任务全部重置。
- 能写文件时，每写完一个文件就读回来，确认内容完整；不能写时按 C 档交付并说明验证范围。
- 用户选择建立项目总表且有写入权限时，在总表里登记一行；用户选了"不建总表"就跳过，不能写时提供可自行登记的内容并说明未写入。

## 第 5 步：跑一次启动检查
A 档运行 init 脚本，B 档按 startup-check.md 逐条检查。能写文件时把结果记录在 progress.md 和 session-handoff.md；C 档只有实际能读或运行时才做相应检查，否则提供人工清单并如实标明未检查。跳过检查不是通过；检查失败时先修复，修不好就汇报；检查未完成时说明原因和未检查范围，不能宣称全部通过。检查时产生的临时文件当场删掉。

## 第 6 步：汇报，然后停下
告诉用户：建了什么、放在哪、启动检查结果、第一个任务是什么、还缺哪些信息。
建议用户开一个新对话问一句"这个项目是干什么的，做到哪了"，看智能体能不能答上来。
不要自己接着开工。

## 兜底：进入已有项目时
本 Skill 被加载、当前文件夹里又有 AGENTS.md 时，先读 AGENTS.md，再按它的"开工"步骤走，不管平台有没有自动加载过。各平台情况见 references/agent-compat.md。

## 不要做
- 不为单个项目生成专门的执行 Skill。找项目靠项目总表和项目里的 AGENTS.md。
- 模板升级后不自动修改已有项目。要升级就走体检模式，由用户逐个确认。
- 规则里不写死任何本机路径、平台名或工具名。
