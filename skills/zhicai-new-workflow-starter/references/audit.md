# 体检打分与旧项目接入

## 体检：五项，每项 0～2 分

| 项目 | 2 分 | 1 分 | 0 分 |
| --- | --- | --- | --- |
| 说明书（指令） | 有 AGENTS.md，150 行以内，写清开工、硬约束、完成定义、文件地图 | 有，但太长或缺其中一块 | 没有，或文件名不标准，智能体读不到 |
| 状态 | feature_list.json 格式正确，最多一个 in_progress，progress.md 是最新的 | 有，但过期或格式不对 | 没有 |
| 验证 | 合格标准写得具体，有能运行的启动检查，完成的任务都有证据 | 有标准但含糊，或全靠人工 | 只有占位符，或没有 |
| 范围 | 一次只做一件，每个任务写了"不碰什么" | 有规则但没落到任务上 | 没有 |
| 收尾 | closing.md 有干净状态清单，下一轮不用人工修就能开工 | 有收尾，但不检查能不能接着干 | 没有 |

报告格式：每项先给分，再写一句原因和具体改法。分数只作参考，不论得分多少，都要逐项检查完整项目的必备架构。只给建议，用户逐条同意后再改。

## 旧项目接入（项目原来不是按这套结构建的）

适用：已有项目的接管和体检，不以分数决定是否盘点必备架构。

### 第一步：只盘点，不动手
列出已有文件和子文件夹及用途。逐项列出完整项目的必备、按能力选择和用户可选项，标明：已有可用、已有等效文件及路径、缺失、无需建立或未验证。区分 Skill 包自身文件和项目文件，不要把全部包文件复制进项目。拿不准的标"待确认"，问用户。

同时识别稳定业务分区、原文及元数据的关联、当前成果位置和程序依赖。已有目录能找到材料时优先补地图，不重新设计全部目录；未发布备选、历史稿与已验收状态按内容和较新状态记录判断，不能仅看文件夹名。来源/批次不明的保留疑问，不猜归属。

### 第二步：认一认，旧东西对应新版的哪一个

| 旧项目里常见的 | 对应新版 | 怎么接 |
| --- | --- | --- |
| CLAUDE.md、.cursorrules、README 里写的规则、自己起名的"说明""规范" | AGENTS.md | 把开工步骤、硬约束、完成标准提炼进 AGENTS.md；原文件不删。原有 CLAUDE.md 不覆盖，问用户能不能在第一行加 @AGENTS.md |
| 待办、任务清单、看板、表格 | feature_list.json | 逐条转成任务；旧记录说已完成但拿不出证据的，暂标 blocked，notes 写明“历史记录称已完成，证据待核实”，保留原记录并请用户协助确认；不编造证据。核实并记录证据、自检通过后才能转 awaiting_review，用户认可后再转 passing |
| 进度笔记、工作日志、周报 | progress.md 或经确认的等效进度文件 | 先确定唯一事实源；可沿用现有文件，需同步 AGENTS、收尾及检查的真实路径，不重复维护两份进度 |
| 交接记录、待办接续说明 | session-handoff.md 或经确认的等效交接文件 | 确认现有文件能承担交接；没有则列入补建方案，写当前状态、未验证项和下一步 |
| 会议纪要、方案对比、选型记录 | DECISIONS.md | 只摘"决定了什么、为什么" |
| 检查清单、验收标准 | docs/harness/verification.md | 含糊的标准改成能逐条检查的，改之前问用户 |
| 成品、输出文件夹 | 确认的实际成果位置（默认 deliverables/） | 优先沿用，在文件地图写清用途和权威入口；两套init脚本的成果目录列表、人工检查及closing同步实际路径，不额外建空deliverables应付检查；用户同意才搬 |
| 版本说明、更新日志 | changelog.md（可选） | 问用户还要不要；要就保留原文件，或改名成 changelog.md |
| 对不上任何一类的 | 不动 | 在文件地图里列为"原有资料" |

### 第三步：列清单，等用户说"行"
写清：要新建哪些文件、从哪些旧文件里提炼了什么、哪些文件要改名或移动（默认一个都不动）。

### 接入原则
- 只加不删。旧文件一律保留，除非用户明确说可以删。已有文件是否等效、需要怎样适配及验证须在方案中列明，用户逐项确认后再改。
- 确有混放、需要改名或移动时，先列旧路径→新路径、受影响的地图/进度/交接/笔记/脚本/配置及验证方法，合并到接入方案。获准后实际更新引用并验证，不只提醒后留着失效路径；不把引用路径改写成已验收状态。
- 代码目录遵守现有依赖；原始资料及元数据保持关联。多个业务成果目录可以并存，但同一成果不在默认目录和业务目录各维护一份权威副本。没有真实材料可试放时标明未验证，不造材料充数。
- 接入完成后运行适用的启动检查或人工清单；记录通过、失败和未检查的项目，更新进度与交接。新对话接续须另行实测，不以脚本通过代替。
