# 收尾清单 · Closing

> 两种情况做：① 一次对话真的要结束时；② 用户说"全局更新"时（随时，马上做）。不要每改一个文件就收一次尾。
> 交接单在完整项目创建时已建立；用户说"全局更新"时，一律核对并更新 session-handoff.md，说明已验证和未验证内容。

## 收尾步骤
1. 更新 feature_list.json：状态、证据、notes。
2. 更新 progress.md："当前已验证状态"，再加一条本轮会话记录。
3. 本轮有重要决定（选了方案、换了方向、改了规则）：问用户要不要记进 DECISIONS.md。
4. 本轮出过错或被用户纠正：在 docs/harness/lessons.md 记一条。
5. 有产出：存入项目已确认的业务/成果位置，任务清单和产出记录引用实际路径；已有成品不再复制或搬到另一份默认目录。没有其他约定的新任务可用 deliverables/{任务 ID}-{short-name}/ 并写好 record.md。多个导出格式可以同处，不能因此维护两份权威源稿。
6. 有 changelog.md，且本轮改了规则或交付物：记一条。
7. 核对并更新 session-handoff.md：写当前状态、已验证与未验证事项、问题和下一步，与 progress.md 一致。
8. 删掉本轮产生的临时文件。
9. 再跑一次启动检查，确认下一轮能直接开工。
10. 有项目总表的，顺手更新本项目的状态。
11. 向用户汇报：做了什么、检查结果、还有什么问题；有 awaiting_review 的任务，请用户审。

## "全局更新"的汇报格式
用户说"全局更新"时，做完上面的步骤，按这个格式汇报：

    全局更新完成
    - 改了哪些文件：{文件名 + 一句话说改了什么}
    - 当前进度：已通过 {x} 个 / 待你审 {x} 个 / 进行中 {x} 个 / 未开始 {x} 个
    - 没解决的问题：{没有就写"无"}
    - 下一步：{下一个任务 ID 和名称}
    - 换 AI 接手：让它先读本项目根目录的 AGENTS.md

## 干净状态检查
- [ ] 启动检查能通过
- [ ] 任务状态是真实的，没有虚标的 passing
- [ ] 没有做了一半却没记下来的东西
- [ ] 临时文件已清理
- [ ] session-handoff.md 已更新，与当前进度一致，未验证内容没有写成通过
- [ ] 文件地图、产出记录、检查和收尾使用同一实际成果位置；涉及改名或搬动的引用已同步
- [ ] 下一轮对话不用人工修，就能按 AGENTS.md 直接开工
